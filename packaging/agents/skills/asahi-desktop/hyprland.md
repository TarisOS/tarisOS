# Hyprland Configuration

Read this before changing keybindings, monitors, window rules, or any other Hyprland (window
manager) configuration.

Hyprland is configured in Lua. TarisOS's config is the system's (it updates with the system), and
your own file goes on top of it:

```
/usr/share/taris/hypr/
├── hyprland.lua     # TarisOS's config: apps, binds, look (package-owned: don't edit)
└── taris.lua        # The shell's integration: binds, gestures, window style (don't edit)
~/.config/hypr/
├── hyprland.lua     # Loads /usr/share/taris/hypr/hyprland.lua (leave it as it is)
└── user.lua         # YOUR changes: loaded last, so they win over everything before
~/.config/taris/
├── window-style.conf    # Window style page: border, gaps, corners, animations (see taris skill)
└── hypr-settings.lua    # Generated by the Displays and Keyboard pages (don't edit)
```

`user.lua` may not exist yet: create it. It is plain Lua with the `hl` API, e.g.:

```lua
hl.config({ decoration = { rounding = 8 } })
hl.bind("SUPER + E", hl.dsp.exec_cmd("nautilus --new-window"))
```

**Key behaviors:**
- Hyprland reloads on save; force it with `hyprctl reload`
- After ANY Hyprland config change, validate with `hyprctl reload` followed by `hyprctl configerrors`
- If `hyprctl configerrors` reports errors, fix them and rerun until clean or until a real blocker
  is identified
- Gaps, border size, corner rounding and the border colours are on Taris's Window style page
  (`window-style.conf`); keyboard, trackpad and monitors on its Keyboard and Displays pages. Prefer
  those over `user.lua` for these settings, so the settings app stays accurate.

## Keybindings

List the current bindings: `hyprctl binds`

`SUPER + K` lists every keyboard binding that has a description (not the Touch Bar's keys or the
mouse's), so give each new keyboard binding a short one (the action in a few words, like the
defaults):

```lua
hl.bind("SUPER + Y", hl.dsp.exec_cmd("kitty -e yazi"), { description = "Yazi" })
```

TarisOS's default bindings:

| Keys | Action |
|------|--------|
| `SUPER + RETURN` | Terminal (kitty) |
| `SUPER + B` | Browser (Chromium) |
| `SUPER + E` | File manager (Nautilus) |
| `SUPER + SPACE` | App launcher |
| `SUPER + TAB` / `SUPER + GRAVE` | Window overview |
| `SUPER + ESCAPE` | Power panel |
| `SUPER + L` | Lock |
| `SUPER + V` | Clipboard history |
| `PRINT` | Screenshot |
| `SUPER + SHIFT + R` | Screen recording (region) |
| `SUPER + W`, `CTRL + Q` | Close window |
| `SUPER + F` | Fullscreen |
| `SUPER + SHIFT + M` | Maximize |
| `SUPER + M` | Minimize to the dock |
| `SUPER + T` | Toggle floating |
| `SUPER + J` | Toggle split |
| `SUPER + arrows` | Move focus |
| `SUPER + 1-9` / `SUPER + SHIFT + 1-9` | Go to / move window to workspace |
| `SUPER + S` / `SUPER + SHIFT + S` | Show or hide the special workspace / move the window there (off on Settings > Panels > Taskbar > Workspaces) |
| `fn` twice | Switch input source (Settings > Keyboard & trackpad picks another way) |
| `fn` held for 1 second | Emoji picker |
| `SUPER + A` | Show or hide the coding agent's workspace |
| `SUPER + N` | Notification sidebar |
| `SUPER + COMMA` | Settings |
| `SUPER + K` | Every keyboard shortcut (a list in the shell) |

**IMPORTANT: When re-binding an existing key:**

1. Check existing bindings: `hyprctl binds`
2. If the key is already bound, call `hl.unbind(...)` BEFORE the new `hl.bind(...)` in `user.lua`
3. Tell the user what the key was previously bound to

```lua
-- Unbind existing SUPER+E (was: file manager)
hl.unbind("SUPER + E")
hl.bind("SUPER + E", hl.dsp.exec_cmd("kitty -e yazi"))
```

The keyboard layout starts as the one chosen on the setup screen (`localectl`); the Keyboard page
changes it for the account.

## Display/Monitors

Prefer Taris's Displays page. By hand, in `user.lua`:

```lua
hl.monitor({ output = "eDP-1", mode = "preferred", position = "auto", scale = 2 })
hl.monitor({ output = "HDMI-A-1", mode = "2560x1440@144", position = "auto", scale = 1 })
```

List monitors and supported modes: `hyprctl monitors all`

## Window Rules

**CRITICAL: Hyprland window rules syntax changes frequently between versions.**

Before writing ANY window rules, fetch the current documentation from the official Hyprland wiki:
- https://wiki.hypr.land/Configuring/Basics/Window-Rules/

DO NOT rely on cached or memorized window rule syntax. Check `hyprctl version` and use the syntax
for that version. Rules go in `user.lua`.
